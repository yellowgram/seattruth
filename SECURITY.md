# Security

## Private vulnerability reports

Do not open a GitHub Issue with a proof of concept, exploit steps, or a zero-day. Do not paste live Stripe keys, Polar tokens, database URLs, Slack webhooks, or customer billing details into Issues or pull requests.

Report privately by email to **hello@yellowgram.dev** with subject `SeatTruth security`. Prefer a short description and a redacted repro. Do not attach live secrets.

You can also use GitHub private vulnerability reporting for this repository:

https://github.com/yellowgram/seattruth/security/advisories/new

If that page says reporting is turned off, email hello@yellowgram.dev instead. Do not open a public Issue that contains exploit detail.

## Support is a different path

[SUPPORT.md](SUPPORT.md) is best-effort help with using SeatTruth. It is not permission to post exploit details while a private report is pending.

Entitlement correctness in your production is yours. SeatTruth is MIT licensed ([LICENSE](LICENSE)) and has no warranty. This policy does not add auto-fix, hosted reconcile, or a warranty that a comparison is correct.
